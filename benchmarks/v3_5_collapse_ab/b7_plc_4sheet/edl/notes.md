## Brutally Honest Feedback on Multi-Sheet EDL v3.5.0

### What Worked Exceptionally Well
1. **Speed & Scale**: Compiling, verifying 24 formal rules (`E1`–`E16`), routing 168 net-sheet routes, and exporting a 5-file hierarchical KiCad 9 project for **210 components / 144 nets** took **< 1 second per iteration**. On raw KiCad S-expressions, a 210-part 4-sheet schematic would be completely unmaintainable; in EDL, refactoring layout coordinates or fixing an electrical issue takes seconds.
2. **Zero-Friction KiCad 9 ERC Parity**: Getting **0 errors and 0 warnings** from `kicad-cli sch erc --severity-all` on a 210-part multi-sheet schematic with STM32F407, LAN8720A, RJ45 MagJack, relays, optocouplers, digital isolators, RS-485, and CAN — including `extends`-derived symbols like `LM2596S-ADJ`, `AMS1117-3.3`, `2N7002`, and `W25Q128JVS` — is a massive achievement for EDL v3.5.0's exporter.
3. **`E15` Isolation Barrier Verification + `E6` Graph Proof**: Combining topological galvanic isolation proof (`require galvanic_isolation(...)` across all 3 domain pairs) with geometric wire-crossing verification (`E15` on vertical red dashed `divider`) caught and proved safety isolation both electrically and visually.
4. **`rect:` + `place ... center` + `edl inspect --zones --nets`**: Literal zone rectangles and exact grid placement gave deterministic, publication-grade schematics without fighting an unpredictable auto-placer, while `E12` guaranteed 0 overlaps across all 210 parts on the first build!
5. **Auto-merged Decoupling Rails & `E14` Thermal Catch**: The shared horizontal decoupling rail on `MCU_Core` and `Ethernet_PHY` rendered cleanly automatically, and `E14` legitimately caught `0.1W` 0603 resistors on 49.9Ω Ethernet terminations before export.

### Friction Points & Areas to Improve in Future EDL Versions
1. **Fake `power:*` Symbol Emission for Custom/Isolated Power Rails (Biggest Multi-Domain Pain Point)**:
   - When `routing { power: symbol  ground: symbol }` is enabled, EDL heuristically classifies ANY net starting with `V` (like `VIN_FUSED`, `VIN_FILT`, `V3V3A_RAW`), ending in `_GND` (`ISO_IO_GND`, `ISO_BUS_GND`), or connected to a `power_out`/`power_in` pin (`LDO_ANA_OUT`, `ISO_BUS_5V`) as a power symbol and emits `power:<NetName>` even when `<NetName>` does **not** exist in KiCad's `power.kicad_sym`! That immediately caused **57 KiCad ERC `[lib_symbol_issues]` warnings**.
   - **Suggested fix**: Check whether `<NetName>` actually exists in KiCad's `power.kicad_sym` before emitting a `power:` symbol; if it doesn't exist (e.g., `ISO_IO_GND`, `ISO_BUS_5V`, `VIN_FILT`), automatically fall back to `global_label` (or `label_stub`) instead of generating a broken library reference! Also allow per-net routing overrides (e.g. `net ISO_IO_GND { style: label_stub ... }`) so a sheet can mix real `power:GND`/`power:+3V3` symbols on the logic side with `label_stub` flags on the isolated field side.
2. **Pin Override Syntax Cannot Target Numeric or Hyphenated Pin Names**:
   - Writing `pin "V-": ground` (for `Amplifier_Operational:LM321`) or `pin "8": ground` (for `Connector:RJ45_Bel_SI-60062-F`) fails with `E_PARSE_IDENT`. Because KiCad's op-amp library universally names negative supply pins `"V-"` (`etype: power_in`), single-supply op-amps connected directly to `GND` trigger a false `E2_no_power_ground_short` unless you split off an `AGND`/`GNDA` rail via a star-ground bead. Supporting quoted pin names or pin numbers in `pin "V-": ground` would fix this cleanly.
3. **Stacked Hidden Pins (`U_MCU.27`, `74`, `99`) vs `edl symbols inspect`**:
   - `edl symbols inspect "MCU_ST_STM32F4:STM32F407V_E-G_Tx"` lists pins `10, 27, 74, 99` as separate `VSS` entries, yet `edl build` rejects `U_MCU.27`, `U_MCU.74`, `U_MCU.99` as `E_REF_UNKNOWN_PIN` because EDL deduplicates stacked pins onto pin `10`. `edl symbols inspect` should clearly flag stacked/collapsed pins (or `edl build` should accept stacked pin numbers as aliases for the primary pin).
4. **Zone Border Auto-Expansion Can Touch Neighboring Zones**:
   - Even with explicit `rect:`, EDL slightly expands a zone's rendered box to encompass external global labels/wires (e.g., `Ethernet_PHY` expanded to `y=243.84mm` and touched `Ethernet_RJ45` at `y=241.30mm` over its title text). Adding a zone-to-zone overlap warning (`E12b`) or warning when a zone auto-expands past its declared `rect:` would catch these visual collisions during `edl build` without needing PNG inspection.
5. **Minor KiCad Netlist Annotation Warning & Title Block Width**:
   - `kicad-cli sch export netlist` emits `Warning: schematic has annotation errors` (even though `erc` is 0 errors / 0 warnings and there are 0 duplicate or `?` refs — likely due to hierarchical sheet instance path table metadata in KiCad 9). Also, `E11` doesn't check whether a long sheet `title:` string overflows the KiCad title block width.
6. **Resistor Value Unit Ergonomics**:
   - Writing `4.7k` instead of `4.7kOhm` (or bare `470` instead of `470Ohm`) fails with `E_UNIT_UNKNOWN`. Allowing standard EE shorthand (`4.7k`, `100R`, `1M`) in `value:` would cut friction for hardware engineers.
